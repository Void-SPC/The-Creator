# The-Creator

Мастерская внутри Roblox: автор строит карты, собирает модели и существ, вручную делает анимации по ключевым кадрам, задаёт логику блоками или текстом, тестирует карту и публикует её. Другие игроки запускают опубликованную карту по коду или из каталога мастерской. Управление рассчитано на планшет и телефон, мышь и клавиатура тоже поддерживаются.

Мастерская готовится к загрузке в плейс игры «Офисы» вместо неё; исходный Office сохранён отдельно. Подробности, перенос Монеты-джентльмена и Инспектора и публикация описаны в [OFFICE_RU.md](OFFICE_RU.md). Правило оформления интерфейсного текста из раздела ниже подходит и для Office.

Сервер — единственный источник правды. Клиент применяет правку у себя сразу (объект двигается на экране, пока тянут ручку) и отправляет ту же операцию на сервер. Сервер применяет её функцией `Ops.apply` с проверкой `Format`, а при отказе присылает свою копию.

## Запуск в Roblox Studio

1. Установите [Rojo](https://rojo.space) 7 и плагин Rojo для Studio.
2. В корне репозитория выполните `rojo serve`, в Studio откройте пустой плейс (Baseplate) и нажмите в плагине Rojo «Connect». Второй вариант: `rojo build -o Workshop.rbxlx`, затем откройте файл.
3. Опубликуйте плейс (File → Publish to Roblox) и включите Game Settings → Security → Enable Studio Access to API Services. Без этого DataStore недоступен и мастерская хранит данные только в памяти сервера (об этом пишет предупреждение в Output).
4. Нажмите Play. В меню выберите «Демосцена» или «Новая карта».
5. Для проверки второго игрока выберите Test → Clients and Servers → 2 Players → Start. В первом окне опубликуйте карту, во втором нажмите «Ввести код».
6. Для планшета и телефона включите Device Emulator (Test → Device) и выберите, например, iPad или iPhone в альбомной ориентации.
7. Администраторы: владелец плейса и ID из `src/server/Config.luau` (`ADMIN_USER_IDS`, `ADMIN_GROUP`). В Studio администратор каждый.

Тесты ядра без Studio: `tools/run_tests.sh /путь/к/luau` (CLI из релизов luau-lang/luau). Скрипт собирает модули в один файл, эмулируя дерево Rojo, запускает тесты и проверяет интерфейсные строки.

## Сквозной сценарий на планшете

1. «Новая карта» → вкладка «Карта» → «Каталог» → «Комната». Касание выбирает объект, ручки «Двигать», «Вращать», «Размер» на левой панели, камера: один палец вращает, два двигают и приближают. «Сетка» переключает шаг 1, 0.5 и выключено. «Отменить» и «Повторить» есть на панели и на Ctrl+Z/Ctrl+Y.
2. Шкаф: «Фигура» → «Блок» несколько раз, ручками и полями «Размер» собрать стенки. Включить «Несколько», выбрать детали, нажать «Склеить». Модель переносится целиком; «Править модель» открывает детали снова; «В «Мои модели»» сохраняет её в библиотеку автора.
3. «Назначить» → «Назначить как шкаф». Появятся три маркера: вход (зелёный), внутри (жёлтый), выход (красный). Кнопки «Точка входа», «Позиция внутри», «Точка выхода» дают ручки для маркера. «Клип входа EnterCloset» и «Клип выхода ExitCloset» открывают их на шкале анимации (дорожки `PlayerRoot` и `Camera`).
4. «Каталог» → «Лампа», «Дверь». Латинские имена задаются в свойствах (например `HallLamp`, `FrontDoor`).
5. Вкладка «Логика» → «Событие» → «Когда открыта дверь» → цель «Выбрать на карте» → касание двери. «+ Действие» → «Изменить свет» → лампа, «Включить» = Нет.
6. «Тестировать» запускает черновик. «Опубликовать» показывает код карты. Второй игрок вводит код в меню.

Демосцена уже содержит всё это: комнату с коридором, дверь `FrontDoor`, книжный шкаф, лисика `Fox` с клипами «Появление», «Ходьба», «Бег», «Прыжок», «Атака», «Скример», лампу `HallLamp`, точки `NoisePoint` и `EscapePoint`, шкаф `Closet01`, табличку и NPC «Сторож» с длинной репликой. Логика: дверь открыта → лисик появляется и бежит на шум → реплика и «Скример» → на метке «Погасить» гаснет лампа → после клипа лисик убегает к `EscapePoint`. Любую цель можно заменить: логика хранит ID, а не имена.

## Возможности по разделам ТЗ

**Карты и модели.** Комнаты, коридоры, этаж выше, лестницы и стены из каталога; старт игрока, двери, лампы, зоны срабатывания, точки назначения (точки связываются в маршрут полем «Следующая точка»). Фигуры: блок, сфера, цилиндр, клин, угловой клин; размер, поворот, цвет, материал, текстура из списка (`Catalog.TEXTURES`, сервер не принимает другие). «Заморозить» запрещает перемещение и поворот в редакторе (сервер тоже проверяет), размер меняется симметрично, физика в игре задаётся отдельными переключателями «Закреплён в игре» и «Твёрдый». «Склеить» сохраняет детали, суставы и клипы модели; копии получают новые ID, внутренние ссылки копируемой группы переводятся на копии.

**Существа и NPC.** Вкладка «Существа»: «Новый» (сегменты рук и ног) и «Ретро» (цельные блоки), лисик и «Новое существо» с нуля. Внешность правится теми же инструментами, что и любая модель.

**Анимация.** Вкладка «Анимация»: выбрать модель, коснуться детали, задать родителя и точку вращения. Указатель времени перетаскивается по шкале, между ключами видна промежуточная поза. Деталь тянется ручкой, дети по суставам двигаются сразу, ключ записывается при отпускании или кнопкой «Ключ». Есть «Удалить ключ», «Копировать», «Вставить», «Ключ влево» и «Ключ вправо», «Предпросмотр», режимы «Один раз» и «Повтор», метки. Если деталь удалили, её дорожка подсвечивается красным, ключи сохраняются, дорожку можно перенести на другую деталь. Маршрут (`MoveTo`) двигает корень модели, клип двигает части тела, поэтому один клип бега подходит для разных маршрутов.

**Шкафы.** Состояния «Свободен», «Вход», «Внутри», «Выход» (`Closet.luau`). Сервер проверяет расстояние до точки входа, что персонаж жив и не сидит в другом шкафу. Повторное нажатие во время клипа отклоняется. При смерти, выходе игрока, удалении шкафа, завершении сессии или зависании клипа (сторож по длине клипа) шкаф освобождается, персонаж ставится у выхода, камера и управление возвращаются. Сервер ведёт корень персонажа по дорожке `PlayerRoot`, клиент — камеру по дорожке `Camera`.

**NPC и действия.** Приветствие при входе в зону или после взаимодействия, клип приветствия, реплики с паузой и длительностью, место показа над NPC или над выбранным объектом. Цель действия выбирается касанием на карте или из списка, показывается как «Название» и латинское имя, хранится по ID. Удалённая цель подсвечивается в блоке, в свойствах объекта и в результатах «Проверить».

**Логика.** Блоки и текст редактируют одно дерево и пользуются одним набором `Logic/Commands.luau`.

```lua
on DoorOpened(FrontDoor) do
  PlayClip(Fox, "Появление")
  Wait(1.4)
  if LightIsOn(HallLamp) and not DoorIsOpen(BackDoor) then
    MoveTo(Fox, NoisePoint, "Бег", 14)
  else
    Say(Fox, "Кто здесь?", 2)
  end
  for i = 1, 3 do
    Wait(0.5)
  end
end
```

События: `MapStarted`, `DoorOpened`, `DoorClosed`, `ZoneEntered`, `ZoneLeft`, `Interacted`, `ClipFinished`, `MarkerReached`, `ClosetEntered`, `ClosetExited`, `Arrived`. Условия: `LightIsOn`, `DoorIsOpen`, `ZoneHasPlayer`, `ClosetOccupied`, `Chance`. Действия: `PlayClip`, `StopClip`, `MoveTo`, `SetLight`, `Say`, `Wait`, `OpenDoor`, `CloseDoor`, `ShowLabel`, `SetVisible`, `PlayCutscene`. Код игрока не превращается в Luau и не исполняется через `loadstring`: он разбирается в дерево и исполняется интерпретатором только через команды хоста. Лимиты: 5000 операций на запуск, 40000 в секунду, 32 потока, 300 секунд жизни, `Wait` до 60 секунд, цикл до 1000 повторов. Сервер выполняет команды только для объектов текущей карты. Ошибка показывает строку (текст) или блок (блоки), введённый код сохраняется даже с ошибками. При переименовании объекта имя в тексте обновляется.

**Камера и интерфейс.** Камера от первого лица с чувствительностью, полем зрения и покачиванием от 0 до 2 (0 отключает). Для шкафа и `PlayCutscene` камера идёт по дорожке `Camera` и возвращается к игроку. В игре только компактная полоска здоровья (если включена), кнопка выхода из шкафа внутри шкафа и маленькая кнопка «Вернуться в редактор» у автора в тесте. Админ-кнопка стоит в свободной области верхней панели рядом с меню Roblox (`GuiService.TopbarInset`), каждое действие проверяется на сервере.

**Тексты.** Надпись на поверхности (на табличке, на двери) или над объектом, перенос строк, размер, цвет. Реплика показывается в выбранном месте и только на заданное время. Вкладка «Тексты» показывает самую длинную реплику в кадре телефона 667×375 тем же кодом, что и игра (`Play/Bubble.luau`). Всё, что увидят другие игроки (надписи, реплики, текст `Say`, название карты), проходит `TextService:FilterStringAsync` → `GetNonChatStringForBroadcastAsync` при тесте и публикации. Если фильтр недоступен, карта не запускается и не публикуется.

**Черновики и публикация.** Формат с полем `format` и цепочкой миграций (`Format.migrate`). Автосохранение каждые 20 секунд при изменениях, сохранение при выходе игрока и `BindToClose`. «Сохранено» появляется только после успешного `UpdateAsync`. Ошибка чтения возвращает ошибку, а не пустую карту, и ничего не записывает. Блокировка сессии не даёт двум серверам перезаписать друг друга: второй открывает карту только для просмотра и пробует снова. Публикация пишет неизменяемую версию `pubv:<код>:<номер>` и затем указатель `pub:<код>`, правка черновика её не трогает.

## Правило оформления интерфейсного текста

Все встроенные строки собраны в `src/shared/UiText.luau`. Короткие подписи (`L`) идут без конечной точки и без точки-разделителя: «Сохранено», «Клип входа» и `EnterCloset` на второй строке, «Код карты» и сам код на второй строке. Подсказки (`H`) состоят из полных предложений. Проверка `UiText.lint()` (тест `UiTextSpec`) и `tools/lint_ui_text.py` (все остальные кириллические литералы) запускаются вместе с тестами. Десятичные числа, версии и синтаксис кода сохраняют точки. Авторские названия и реплики хранятся как ввёл автор и проходят фильтрацию Roblox.

## Что проверено

Проверено автоматически (62 теста в CLI luau 0.700, плюс компиляция и статический анализ всех файлов):

- вход в шкаф и выход, быстрое двойное нажатие (второй клип не запускается), занятый шкаф, смерть во время клипа (освобождение и игнорирование устаревшего завершения), сторож зависшего клипа;
- шкаф после поворота и переноса: точки входа, внутри и выхода переезжают вместе с ним, игрок у входа смотрит на шкаф при поворотах 0, 90, 180, −90 и 37 градусов, клипы заканчиваются в нужных точках;
- удаление цели события: блоки с этой целью помечаются как требующие новой привязки, остальная логика цела;
- восстановление черновика после переподключения: открывается последняя подтверждённая версия, несохранённая правка не появляется, ошибка чтения ничего не записывает, повреждённые данные не открываются пустой картой, второй сервер видит блокировку;
- запуск опубликованной карты «со второго клиента» на уровне хранилища: другой экземпляр хранилища загружает версию по коду, правка черновика её не меняет, вторая публикация даёт версию 2 с тем же кодом, первая остаётся доступной;
- сквозной сценарий из раздела 7: комната, шкаф из фигур, склейка, назначение шкафа и правка клипа входа, «Мои модели», лампа, реакция на дверь, сохранение, публикация, запуск по коду и срабатывание логики;
- суставы (уши следуют за головой, ухо поворачивается отдельно), обратная задача для ручки, интерполяция, режимы клипа, метки, дорожка удалённой детали;
- логика: демосцена в блоках и тексте даёт одно дерево, ошибки указывают строку и блок, лимит операций, лимит потоков, ошибка одного обработчика не останавливает другие, переименование цели в тексте;
- правки, отмена и повтор, «Заморозить», атомарные пакеты, уникальные латинские имена, защита служебных полей;
- правило точек во всех встроенных строках интерфейса.

Не удалось проверить в этой среде, потому что здесь нет Roblox Studio: поведение экземпляров Roblox (ручки `Handles` и `ArcHandles` на сенсорном экране, жесты камеры редактора, камера от первого лица, анимация персонажа в шкафу по сети, реплики `BillboardGui`, ProximityPrompt, DataStore, TextService), реальный запуск двумя клиентами и читаемость длинной реплики на устройстве. Эти сценарии нужно пройти в Studio по шагам выше. Если ручки плохо отвечают на касание, в свойствах объекта есть кнопки «Точный сдвиг» (X, Y, Z и поворот по 15 градусов).

## Известные ограничения

- Существа идут по маршруту по прямым между точками, без поиска пути.
- Сессии игры живут на том сервере, где их запустили; второй игрок по коду получает свою копию на своём сервере. Для общей сессии нужен `TeleportService` с зарезервированным сервером.
- Масштабировать модель целиком нельзя, размер меняется у отдельных деталей в «Править модель».
- В блочном режиме переменные показываются текстом; их удобнее править в текстовом режиме.
- Текстур в каталоге две встроенные; свои изображения добавляются строкой в `Catalog.TEXTURES`.
